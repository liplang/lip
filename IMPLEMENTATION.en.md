# LIP 1.0 implementation and validation

[English](IMPLEMENTATION.en.md) | [简体中文](IMPLEMENTATION.md)

The [LIP 1.0 specification](spec/LIP-1.0-SPEC.en.md) is the language authority. This repository implements entries, values/pure functions, control structures, structured Flows, static modules, Claims, graph scheduling, and a unified Host boundary through interpretation and actual Go generation. This guide maps specification sections to repeatable regression evidence. HTTP is optional; the optional durable profile is unimplemented.

Module/call support reuses compiler, checker, evaluator, scheduler, and backend. Loading/linking is centralized in `script/modules.go`, without a second execution machine. Parameters/globals resolve lexically. Claim reads use the current environment rather than capturing same-named module values through node store names. native_data/native_release lower only helper names unoccupied by declarations, parameters, bindings, stores, or aliases; dependency helpers retain their origin during linking. Pipeline targets remain static for the ordinary checker instead of bypassing it through native AST rewriting.

## Concurrency and retained values

Any positive Go `int` is a valid leaf allowance; zero selects one for ordinary Run and negative values return E-VALUE. Fixed-size event storage, bounded completion batches, active-candidate sorting, and indexed effect/barrier sets avoid allocation proportional to the configured ceiling and repeated sorting of completed history. Workers are created only for actual work. Node-budget exhaustion stops graph construction immediately. Parent/child calls share the allowance; child and permit waits yield it. ResourcePool limits remain independent of scheduler parallelism.

Evidence: `ArbitraryParallelismOverlap`, `ParallelismConfiguration`, `GoBackendArbitraryParallelism`, `LargeParallelNestedFlowsAndPermits`, `LargeParallelCancellationReleasesPermits`, and `GraphConstructionStopsAtNodeBudget`. The overlap test checks actual simultaneous provider calls and their drain, rather than only accepting a numeric flag. Its normal matrix includes non-power-of-two limits and partial final waves; the opt-in form below tests every requested call concurrently. On 2026-10-15 a registered blocking ReadOnly provider reached 73,295 simultaneous calls; this demonstrates scheduler overlap, not equivalent CPU throughput or arbitrary external-service capacity.

```sh
make prepare
env GOCACHE="$PWD/.build/cache" GOTMPDIR="$PWD/.build/tmp" \
    TMPDIR="$PWD/.build/tmp" GOPATH="$PWD/.build/gopath" \
    LIP_STRESS_PARALLELISM=73295 \
    go test ./tests -run '^TestArbitraryParallelismOverlap/73295$' -count=1 -v
```

Completed lexical regions release node values/environments and loop sources while retaining status, errors, identities, and source lengths required by After. Child Flow stores are released at completion; its immutable Data output stays until transferred to the waiting caller. Frozen closures and shared Data retain independent references. Top-level session results remain until transaction commit. `CompletedScopesReleaseLocalValues` measures the live heap during a run after large pure temporary allocations in child/branch/loop scopes; `CoreCompositionConformance` checks shared outputs, closures, and Claims in both interpreter and generated programs. Exact last-use cleanup inside still-active scopes is not implemented. Graph records, live Claims, outputs, native references, and the memory journal still retain necessary data; there is no constant-memory or fatal OOM recovery guarantee.

Named and anonymous functions freeze only the external names they use; mutually recursive named functions preserve their original identities. Declaring an unrelated function therefore does not retain large unbound session values. Pipeline temporaries belong to the current pipeline scope and are not external closure captures. `SessionDeleteReleasesUncapturedValues` measures heap retention after unbinding; `SessionPipelineClosures` and `CoreCompositionConformance/closure_pipeline` check nested pipeline closures and name reuse through the REPL, interpreter, and actual generated programs. `FuzzSessionTransactions` additionally checks arbitrary-cell failure transactions, recovery, and deletion/reuse.

## Tools, teaching, and scope

CLI run/emit-go/build/serve share one frozen SourceSet, limited to 4,096 sources/64 MiB. BuildInfo exposes SourceTable, DependencyLock, and revision. SourceTable sorts by SourceID; StaticSite independently uses root-first order. Generated programs fix entry/snapshot and retain metadata without reparsing/interpreting LIP.

`DefaultMaxFrames` is 10,000 active non-tail function frames per leaf evaluator. `Options.MaxFrames` and the run/repl/serve/generated executable `-frames` flag accept positive overrides; zero uses the default, and negative values fail configuration rather than disabling the guard. Direct/indirect/mutual calls and map/fold callbacks share the same invocation guard; proper tail calls reuse it. Exhaustion produces a positioned E-BUDGET, a failed Report with no EntryOutput, no CLI success output, and no failed-cell bindings. HTTP maps it to the existing fixed 500 error response. The REPL and handler remain available for subsequent work. This is a proactive frame budget, not per-run memory accounting or recovery from fatal native runtime/OS exhaustion; hosts should retain suitable instruction, allocation, concurrency, and deadline limits.

REPL cells retain successful immutable values, fn/Flow declarations, and closures without rerunning actions. The shared declaration parser, checker, linker, native lowering, and graph runtime support script syntax, including static Data, exports, LIP imports, Claims, and statement/value forms of control flow. Flow calls and pipelines create fresh child graphs/stores. Top-level Claim stores finish within one cell; only completed Data snapshots persist. :begin/:end groups whole scripts and forward declarations; -project selects the import root, and imported source closures stay frozen until reset. :run provides independent file execution with entry/project/input/output options. The REPL displays expression and binding results: fmt.Print/Printf/Println return a byte count after the Go adapter handles their error channel, so that count is displayed too. This is the Go result, not a second print added to the library call.

The session namespace maps public names to immutable per-cell symbols. `Session.Delete(names...)` and CLI `:del name[,name...]` validate the entire batch before removing public bindings, regardless of contents. Later cells may reuse each name across binding kinds; retained closures and Flows keep prior references, imports, and original source tokens. Reachability from public bindings and retained Flow dependencies prunes unused saved values/definitions. Import caches and native lifetimes remain explicit; unbinding does not replay actions or close resources. `SessionDeleteBindings`, `SessionDeleteModuleAlias`, and `InteractiveCLI/delete-bindings` cover cross-kind reuse, old dependencies and proposals, missing/malformed atomic deletion, Claim snapshots, alias replacement, visibility, and reset.

All 19 learn lessons use CompileSourceSet/Run. Entry lessons check both argument modes; module lessons bundle frozen sources. English/Chinese READMEs, guides, CLI help, and lessons describe the same boundaries; normal interactive text and example comments use English.

HTTP accepts explicit Host contracts, without a request-scoped generic native bridge. Files/REPL/generated programs support generic Go/Python. Interpreted automatic Go imports use a development bridge requiring the Go toolchain, CGO, and plugin support; generated Go exports and inferred generic instances are linked at build time and need no toolchain during calls. Unknown generic argument types need explicit concrete registration in HostSource. Python needs its runtime/packages. MemoryJournal records/replays only within the process and cannot recover crashes. Durable begin/persistence/crash/reconcile conformance is outside current support.

## Correctness and Host integration boundaries

Saved REPL proposals retain their original normative Ops analysis. Container projections, function results, and carry results stay Unknown across cells and aliases; a saved runtime operation identity cannot authorize parallel execution. `SessionPreservesProposalOps` checks rejection before any provider call while direct saved proposals remain usable in eligible parallel bodies.

List/string indexing now accepts negative safe integers; list index lists preserve order and duplicates. Bracket slicing and `slice(v,start,stop[,step])` share exact integer normalization, clipping, nullable defaults, and negative strides. This replaces the former strict nonnegative slice bounds. Core evaluation and native Data projection share helpers; Go resources support scalar/gather/slice access and Python resources receive native slice objects. Result lists check allocation budgets before allocation; loops check cancellation and instruction budgets. Function/effect values survive selection while normative Ops remain Unknown.

`IndexAndSliceConformance` compares success, failure diagnostics, and allocation budgets with an actual generated executable. `IndexAndSliceSyntaxAndComposition` checks syntax, Unicode scalars, closures, carry, operand order, skipped operands, and conservative Ops. `NativeIndexAndSliceComposition` covers Go resources, Python arrays, native Data fallback, pure siblings, and saved views. `SessionIndexAndSlice` reproduces multi-cell indexing, failed-cell recovery, help, and completion. The container example, 19-lesson course (including `slicing`), REPL help, and both spec/README editions describe the same behavior.

`claim.snapshot` proposals retain their originating run and Flow instance identities, without retaining the live store or its graph. Closures, map, containers, and carry may pass them within that instance. Performing one in a later cell or another instance returns runtime E-RESOURCE before Host authorization, without retargeting a new store or crashing the process. `SessionSnapshotProposalLifetime` checks recovery, failed-cell transactions, and store-name deletion/reuse. `SnapshotProposalComposition` compares interpretation, actual generated programs, and journal replay while checking isolation between two child Flow calls.

Go Data conversion and `native_data` snapshots distinguish active objects by type, address, and slice length. Both accept finite views sharing a backing array; `native_data` additionally accepts differently typed pointers sharing an address while rejecting actual slice/map/pointer cycles. `NativeSharedDataSnapshots` checks those combinations and unselected zero-call branches in the interpreter, generated executable, and persistent session. `GoDataSharedSlicesAndInvalidFieldNames` also covers explicit Go adapters: invalid UTF-8 struct field mappings produce E-VALUE instead of silently becoming null, and completed-call conversion failures retain known_fault with no extra provider calls during replay.

Native provenance tracks individual container positions separately from the containing immutable value. `native_data` returns ordinary Data; capturing snapshots, reading pure fields beside resource references, and selecting pure list elements do not introduce a perform. `NativeSnapshotsAndContainerPurity` checks the interpreter, generated executable, and persistent session. Known Go scalar results follow their Data representation; saved functions and proposals retain result provenance separately from Ops. Pure retained datasets do not allocate a second per-element provenance array: `SessionNativeLargeDataAllocation` guards small-cell allocation with a retained 250,000-element numeric list. Build-only initializer links live outside runtime expression trees, and lexer tokens own their text instead of retaining a whole source buffer through substrings. `SessionNativeMetadataDoesNotRetainInitializers` checks that a closure capturing only a computed length releases a deleted 12 MiB literal.

`Host.BeginRun` and `RunLease.End` allow application-defined run leases and receive run identity, completion error, and journal. Cleanup executes after started operations settle, including cancellation and budget failure; it does not undo writes. `Report.CleanupErrors` retains cleanup faults independently of graph root errors. Native handles carry scope, owner, and generation. File-run handles are revoked at completion; failed cells release new handles without disturbing saved resources. Successful cells retain newly created handles reachable from saved values, closures, proposals, and the result. Resource release removes technical references; business close/commit/rollback remains explicit. `HostRunLifecycle`, `NativeRunOwnershipAndFailedCellCleanup`, `NativePythonFailedCellCleanup`, and `DiagnosticPhases` cover these boundaries; the Python check uses weak references to verify actual object reclamation while retained closures remain usable. Diagnostics identify static, runtime, or Host phase; invalid/foreign/released handles use E-RESOURCE.

Generated programs register automatic Go exports statically, preserve named argument binding, and link concrete generic instances inferred from source argument types and Go result signatures. `GeneratedGoLibrariesWithoutRuntimeToolchain` runs an actual executable with no Go toolchain on PATH; `GoModulePackageDiscoveryWithoutRegistry` also checks a local third-party module. Types unresolved at build time require concrete registration through trusted HostSource. The interactive/interpreted automatic Go development bridge still loads plugins during authorized calls; it remains outside §10.2's static binding requirement. Use explicit statically registered adapters or generated executables for that requirement. The spec has not been weakened to exempt this bridge.

General application resource metadata, cancellation/close behavior, and worker lease isolation remain the embedding Host's responsibility. The default Native Host is intended for one session or file workflow; it provides neither a shared concurrent request worker pool nor complete application resource management. HTTP continues to require explicit Host contracts. These limits prevent treating §10.1–10.2 coverage as universal compliance.

## Practical application checks

`PracticalNativeWorkflows` runs parameterized SQLite aggregation/injection checks, pandas CSV cleanup/grouping, scikit-learn linear regression and a scaling/classification pipeline, NumPy linear solving, SciPy integration/optimization, and Go HTML template escaping/unsafe-URL filtering. Each case runs through interpretation at parallelism 1 and 7, an actual generated executable, and a persistent REPL. Scientific cases require installed packages and explicitly skip when absent; the local environment provides NumPy 2.3.2, pandas 2.3.2, SciPy 1.16.2, and scikit-learn 1.7.2.

`NativeReceiverProposals` verifies requests on Flow/function parameters, nested Go resources, Data wrappers holding resources/callables, saved REPL receivers, name deletion/reuse, and zero-call construction. `NativeModuleReceiverProposals` checks lexical isolation and object-method requests through imported LIP helpers in the interpreter, generated program, and REPL. Explicit receiver requests do not depend on statically tracked native provenance; native adapters resolve nested members only during perform. Ordinary pure object calls retain their existing semantics.

`HTTPPracticalCRUDApplication` runs a shared-storage website with separate list/read/create/update/delete/page entries, business validation, 400/404/409 outcomes, escaped Go HTML templates, and 24 concurrent create/read clients. Invalid input performs zero writes; repeated requests preserve storage without leaking request-local values. HTTP storage and rendering use explicit application Host contracts. The pure-core linear-model example additionally checks centered least squares, prediction, mean squared error, and singular-input rejection across all example execution paths.

Synthetic module lookup/preparation operations use a reserved source-keyword prefix, separating them from real Python paths such as get.once and prepare.once. Adapters strip only the prefix for the current action, once. `NativePythonStateAttributesAndCallOrder` covers those names, nested prepare fields, completion, and the interpreter/generated/REPL paths.

## Validation and environmental boundaries

```sh
make test       # Public API, lessons/examples, actual PTY, actual generated programs
make race       # Interpreter and generated programs, including shared static metadata
make vet
make clean
```

`go run ./tests/reference_numeric -check` independently verifies bits from the specification reference algorithm and runs within make test. Use `-spec spec/LIP-1.0-SPEC.md` to check the Chinese edition. CoreCompositionConformance compares original module diagnostics as well as successful results, without caller wrapping. Dedicated After/barrier/permit tests verify completion sets/prerequisites beyond final-value equality. Native composition passes Go/Python objects through legal pure fn pipelines and then accesses methods/indices, comparing actual generated programs.

Both README editions retain the same three complete program blocks, exercised with named/positional inputs, null/void, module reuse, and parallelism 1/2/4. CLI checks include emit-go/build executables, Go/Python REPL, all bundled script examples through sessions, saved Flow transactions, frozen module imports, multiline statements, real PTY Flow completion/paste, quoted :run paths, bundled lessons away from the repository, and all 19 lessons. Relative links, section anchors, and named evidence are checked with the documents.

The baseline recorded on 2026-10-15 used Go 1.27, Python 3.13, and Linux and passed make test/race/vet. In restricted sandboxes, InteractiveCLI/web-server explicitly skips when TCP listen is denied, while in-memory HTTP/handler checks continue. Platform-plugin/installed-package tests state prerequisites and skips; a skip is not a pass. Current task results are reported separately on delivery.

Validation uses project-local caches/temp directories. Cleanup removes only generated project products; do not deliver `.build`, executables, or Python caches.
