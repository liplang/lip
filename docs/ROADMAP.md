# LIP 路线图

当前版本围绕完整的数据程序：声明输入、构造数据、变换与聚合、输出结果，
再观察依赖图与执行。规则以[语言规范](ALPHA-0.6-SPEC.md)为准。

语法参考 Rust，区间遵循 Python 的习惯。集合遍历用 range → Map → fold，
树与分治用纯递归。Go Host 与 Python Worker 为这些组合提供外部能力。

## 下一步

先收集实际程序中的组合需求、诊断修复步数与 check/run 延迟，再确定改进优先级。

| 使用需求 | 可评估的方向 |
| --- | --- |
| 更快的编辑与验证 | 格式化工具、重复构建的复用、REPL Python 对象的跨单元生命周期 |
| 深递归或大型区间 | 尾调用、惰性迭代或循环 |
| 单 Worker 排队与大数组复制 | Worker pool、Arrow、共享内存或传输优化 |
| 持续输入与状态推进 | 事件或流的执行模型 |

Python 协议、句柄与数据面的详细计划见
[PYTHON-INTEGRATION.md](PYTHON-INTEGRATION.md)。每项新能力同时定义最小规则、
与现有能力的组合方式、错误语义和验证。

## Flow 命名输入候选

当前输入按位置绑定。命名输入可以参考 Python：位置输入在前，关键字输入在后，
按参数名绑定并检查重复、缺失或未知名字。工具选项仍在入口文件前，程序输入
仍在文件后，见[CLI 设计依据](COMPILER.md#cli-设计依据)。

候选设计需要先明确命名输入的文本编码，并保留原样字符串的表达方式。
`run`、独立可执行文件和生成源码将共用 Runtime 的绑定规则。
